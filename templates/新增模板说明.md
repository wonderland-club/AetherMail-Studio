# 新增模板说明

推荐优先使用命令生成空白模板脚手架：

```bash
python create_template.py --template-id demo_notice --subject "测试主题"
```

如需自定义模板描述，可追加：

```bash
python create_template.py --template-id demo_notice --subject "测试主题" --description "测试通知模板"
```

命令默认会创建：

- `template.py`
- `template.md`
- `attachments/README.md`
- `attachments/slot1/`
- `attachments/slot2/`
- `attachments/slot3/`

其中 `attachments/slot1~3/` 是默认创建的附件槽位。即使暂时不用附件，也会先创建出来。  
当前项目只有一种脚手架，不再区分 `basic/ai` 两种模式。AI 能力是模板内部的可选扩展点。

## 模板目录约定

在 `templates/<template_id>/` 下添加模板时，请遵循以下规则：

1. 目录命名：`<template_id>` 全局唯一，建议与 `TEMPLATE_ID` 一致。
2. 必备文件：
   - `template.md`：邮件正文 Markdown，使用 `{{&VAR}}` 占位符。
   - `template.py`：定义模板元数据与渲染函数。
3. `template.py` 中的必填项：
   - `TEMPLATE_ID`：非空字符串，模板唯一标识。
   - `DEFAULT_SUBJECT`：非空字符串，邮件固定主题。
   - `render(data, renderer)`：必须可调用，并返回 Markdown 字符串。
4. `template.py` 中的可选项：
   - `DESCRIPTION`：模板说明，展示在 `/templates` 中。
   - `REQUIRED_FIELDS`：请求 `data` 中的必填字段列表。
   - `ATTACHMENT_SLOTS`：模板自带附件槽位列表。

## 统一脚手架参考结构

```python
from pathlib import Path

TEMPLATE_ID = "your_id"
DESCRIPTION = "模板描述（给自己看的）"
DEFAULT_SUBJECT = "默认主题"
REQUIRED_FIELDS = ["REQUIRED_VAR"]
ATTACHMENT_SLOTS = ["slot1", "slot2", "slot3"]  # 可选；脚手架默认会带上


def _maybe_generate_ai_report(payload):
    """Optional AI hook.

    默认不调用 AI，直接返回空字符串。
    如需启用，可在这里按需接入 src.ai 中的 DoubaoSeed16Service / DoubaoSeed18Service / normalize_markdown，
    并返回要注入到 {{&AI_REPORT}} 的 Markdown 文本。
    """
    return ""


def render(data, renderer):
    md_path = Path(__file__).with_name("template.md")
    md_text = md_path.read_text(encoding="utf-8")
    payload = dict(data or {})

    ai_report = _maybe_generate_ai_report(payload)
    if ai_report:
        payload["AI_REPORT"] = ai_report
    else:
        payload.setdefault("AI_REPORT", "")

    return renderer.render(md_text, payload)
```

默认脚手架里已经预留了 `AI_REPORT`，即使你完全不用 AI，也不会报错。  
如果模板需要自动补一些变量，比如当前时间、当前日期、展示名等，可以继续在 `render()` 中补充后再调用 `renderer.render(...)`。

默认生成的 `template.md` 会包含一段普通正文和一个 `{{&AI_REPORT}}` 占位区域，所以：

- 普通模板：直接编辑正文即可，保留或删除 `{{&AI_REPORT}}` 都可以
- AI 模板：只需要补 AI hook，并决定正文里是否显示 `{{&AI_REPORT}}`

## 附件规则

如需模板自带附件，可在 `template.py` 中声明：

```python
ATTACHMENT_SLOTS = ["slot1", "slot2", "slot3"]
```

然后在 `templates/<template_id>/attachments/<slot>/` 中各放 1 个真实文件。发送时系统会自动附加。

规则如下：

1. 每个槽位目录最多放 1 个真实文件。
2. 隐藏文件和 `README.md` 会被忽略。
3. 某个槽位为空时会自动跳过，不报错。

## AI 可选扩展点

如果模板需要真实调用 `doubao-seed-1.6` 或 `doubao-seed-1.8`，不要在模板里自己直连 Ark SDK。当前项目的推荐方式是复用共享 AI 层。  
AI 是否启用由模板代码内部决定，不通过请求参数或环境变量开关切换。

推荐写法：

```python
from src.ai import AIResponseError, DoubaoSeed16Service, normalize_markdown

def _maybe_generate_ai_report(payload):
    service = DoubaoSeed16Service()
    result = service.generate_structured_json(
        prompt="你的 prompt",
        schema_name="your_schema",
        schema_description="your schema",
        schema={
            "type": "object",
            "properties": {"report_md": {"type": "string"}},
            "required": ["report_md"],
            "additionalProperties": False,
        },
        strict=True,
    )
    report_md = normalize_markdown((result.get("report_md") or "").strip())
    if not report_md:
        raise AIResponseError("AI 文案为空，无法渲染")
    return report_md
```

这样做的好处是：

- `doubao-seed-1.6` 链路配置统一走 `.env` 中的 `DOUBAO_SEED_16_*`
- `doubao-seed-1.8` 链路配置统一走 `.env` 中的 `DOUBAO_SEED_18_*`
- 上游错误、配置错误、响应错误都有统一异常类型
- Markdown 标准化逻辑可复用

## 从普通模板升级到 AI 模板

通常只需要改模板目录内两个文件：

1. `template.py`
   在 `_maybe_generate_ai_report(payload)` 中接入 `DoubaoSeed16Service` 或 `DoubaoSeed18Service`
2. `template.md`
   决定是否展示 `{{&AI_REPORT}}`，以及把 AI 内容放到正文哪个位置

其他部分通常不需要改：

- `/api/send` 请求协议不变
- `TemplateRegistry` 加载规则不变
- SMTP 配置不变

## 占位符与请求体

占位符格式固定为 `{{&VAR}}`。变量名需在请求 `data` 中提供，或在 `render()` 内补充；缺失会返回 400。

请求体示例：

```json
{
  "template": "your_id",
  "smtp_name": "junyan_qq",
  "to": "user@example.com",
  "cc": [],
  "data": {
    "REQUIRED_VAR": "value"
  }
}
```

## 生效方式

模板文件创建完成后，无需修改后端代码。重启服务后即可生效；如果你是在代码里直接操作 `TemplateRegistry`，也可以手动调用 `registry.reload()`。

## 维护矩阵

如果模板协议发生变化，至少要同时检查这些地方：

1. `create_template.py`
   生成器产物是否仍符合最新模板协议
2. `templates/新增模板说明.md`
   文档示例是否仍与生成器和运行时一致
3. `README.md`
   快速开始里的模板入口和说明链接是否仍正确
4. `src/core/template_registry.py`
   运行时加载规则是否仍与模板协议一致

这四处要保持同步，避免出现“生成器产物能创建，但运行时加载失败”或“文档和脚手架不一致”的情况。
